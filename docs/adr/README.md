# Architecture Decision Records

An Architecture Decision Record (ADR) is a short document that captures one significant technical decision: the context that made it necessary, the decision itself, its consequences and the alternatives that were considered and rejected. An ADR is accepted when its decision is taken and is added with the milestone that implements it; where part of the decision concerns a tool that arrives in a later milestone, the record says so in one line and that part is completed then. ADR 0015 is the one such record so far: Jest arrives in milestone 8 and k6 in milestone 9. A record is corrected when it misdescribes the code, but never rewritten to record another decision; a decision that changes gets a new ADR that supersedes the old one. Every record here follows the same outline (Status, Context, Decision, Consequences, Alternatives considered), is written in English and only describes what the code in this repository actually does. Numbers follow the index of the project plan, which is why the sequence has gaps for now: the records between 0001 and 0015 arrive with the domain, the API, the queue, the payment and the mobile milestones.
