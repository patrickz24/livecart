# Architecture Decision Records

An Architecture Decision Record (ADR) is a short document that captures one significant technical decision: the context that made it necessary, the decision itself, its consequences and the alternatives that were considered and rejected. An ADR is accepted when its decision is taken and is added with the milestone that implements it; where part of the decision concerns a tool that arrives in a later milestone, the record says so in one line and that part is completed then. ADR 0005, ADR 0006 and ADR 0015 are the three such records so far: the expiry of the reservations with a payment in flight of 0005 arrives in milestone 5, the LLM fallback of 0006 in milestone 4c, the Jest and k6 parts of 0015 in milestones 8 and 9. A record is corrected when it misdescribes the code, but never rewritten to record another decision; a decision that changes gets a new ADR that supersedes the old one. Every record here follows the same outline (Status, Context, Decision, Consequences, Alternatives considered), is written in English and only describes what the code in this repository actually does. Numbers follow the index of the project plan, which is why the sequence has gaps for now: the records still missing below 0015 arrive with the milestones that implement them (the queue, the payment, the real-time events, the contracts, the white-label app and the observability).
