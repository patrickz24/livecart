# Architecture Decision Records

An Architecture Decision Record (ADR) is a short document that captures one significant technical decision: the context that made it necessary, the decision itself, its consequences and the alternatives that were considered and rejected. An ADR is accepted when its decision is taken and is added with the milestone that implements it; where part of the decision concerns a tool that arrives in a later milestone, the record says so in one line and that part is completed then. ADR 0015 is the one such record left: its k6 part arrives in milestone 9. ADR 0006, ADR 0005 and ADR 0014 were ones too, until milestone 4c completed 0006 with the LLM fallback, milestone 5 completed 0005 with the expiry of the reservations whose payment is in flight, and milestone 6 completed 0014 with the metrics of the shipments; milestone 8 added 0015's Jest part. A record is corrected when it misdescribes the code, but never rewritten to record another decision; a decision that changes gets a new ADR that supersedes the old one. Every record here follows the same outline (Status, Context, Decision, Consequences, Alternatives considered), is written in English and only describes what the code in this repository actually does. Numbers follow the index of the project plan, which is why the sequence has gaps for now: the record still missing below 0015, the contracts (0012), arrives with the milestone that implements it. ADR 0017 records a decision the plan's index did not number: the browser side of the seller's sign-in and of the live stream, which milestone 7 implemented. ADR 0016 is the one record of a design rather than of code: the target hosting, which decision 6 of the plan keeps designed, not executed; [the deployment guide](../DEPLOYMENT.md) holds the design and says what blocks its execution.
